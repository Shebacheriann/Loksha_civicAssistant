1. FILE A COMPLAINT PAGE
Redesign the desktop layout of the File a Complaint page.

- Keep the back button at the top, properly aligned with the page content.
- Keep the four complaint input options:
  • Talk – Describe the issue
  • Text – Add details
  • Photo / Video – Add evidence
  • Location – Confirm location
- These should appear as proper large interactive cards/buttons with icons, arranged cleanly in a responsive 2x2 grid on desktop.
- Each card must clearly look clickable.
- Show a clear selected/completed state ONLY after the user actually enters/completes that information.
- Do NOT pre-check Talk, Text, Photo/Video, or Location when they have not been completed.
- Text should never overlap, wrap badly, or appear outside its card.
- Add a clean progress bar below the page heading. The progress bar should represent completion progress, but DO NOT display text such as "3 of 3 required steps completed".
- These options are NOT all mandatory. A user should be able to submit a complaint without completing every optional field.

BOTTOM ACTION AREA:
- Replace the current stretched Save & Submit button and poorly formatted Save/View buttons.
- Create a professional action section at the bottom.
- Use clearly separated buttons:
  1. Save
  2. Save & Submit
  3. View Complaint
- Buttons should have sensible widths and alignment, not stretch unnecessarily across the entire screen.
- Make the primary action visually prominent while keeping the secondary actions clearly visible.
- Ensure buttons remain properly positioned at the bottom of the complaint content and never overlap other content.

2. COMPLAINT SUB-PAGE NAVIGATION
When the user clicks Talk, Text, Photo/Video, or Location from File a Complaint:

- Do NOT make the main top navigation disappear or become confusing.
- Keep the main website navigation/header unchanged.
- Add a secondary complaint-flow navigation bar directly below the main website header.
- This secondary bar should contain:
  Talk | Text | Photo / Video | Location
- The currently selected section should be visually highlighted.
- Clicking one of these items should switch directly to that complaint section/page.
- The user should be able to move between Talk, Text, Photo/Video and Location without being taken completely out of the complaint workflow.
- Include a clear way to return to the main File a Complaint overview.
- The complaint flow should feel like one continuous multi-step form.

3. LOCATION PAGE
The Location page must support THREE ways of providing a complaint location:

OPTION 1 — USE CURRENT LOCATION
- When the user clicks "Use Current Location", request browser/device location permission at that moment.
- Do NOT request location access immediately when the Location page opens.
- Only request permission after the user explicitly clicks the current-location button.
- If permission is denied, show a clear, friendly error message and allow the user to choose another method.
- After location is obtained, display the coordinates and resolve/show the location on the map.

OPTION 2 — CHOOSE LOCATION MANUALLY ON MAP
- Provide a visible interactive map.
- The user must be able to manually select/pin a location on the map.
- This option must NOT require detecting the user's current location.
- Do not request browser geolocation permission for this option.
- After the user selects a point, display the selected latitude and longitude and the resolved address if available.
- Provide a clear "Confirm Location" action.

OPTION 3 — ENTER ADDRESS MANUALLY
- Provide an address input field.
- The user can type an address manually.
- After entering the address, use the available geocoding/map functionality to locate it on the map.
- Show the resulting location on the map for the user to review.
- The user must explicitly confirm the location before it is marked complete.

LOCATION UI:
- Present the three options as clear cards/tabs/buttons.
- Make it obvious which method is currently selected.
- Do not mark Location as completed until the user actually confirms a location.
- Do not show fake/sample GPS data as though it were the user's real location.
